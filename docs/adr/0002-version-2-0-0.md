# ADR 0002: Supported versions: 2.0.0 (default) and 1.1.2

- **Status:** Accepted · **Date:** 2026-10-17, extended 2026-11-14
- **Requirements:** FR-003

## Decision
Two updates are supported, each with its own entry in `games/xcde/profile.json`:

| Version | Update | `main` build-id | Notes |
|---|---|---|---|
| 2.0.0 | `v262144` | `7e1df8e08d60544b…` | default; full patch set (`patches.py`) |
| 1.1.2 | `v196608` | `92c78bb3dcbbc3f7…` | `patches-1.1.2.py`; same `rtld`/`sdk`/`subsdk0` |

The generator produces code for exact addresses, so the dump's version is detected by build-id and the
matching modules, ROMFS manifest and patch file are used. One build still contains the code of one version:
a binary built from 1.1.2 refuses 2.0.0 files at load time, and vice versa.

## Reason
The last update remains the most stable and the default. 1.1.2 was requested for players whose dump predates
2.0.0; its `main` code differs, so it cannot share the 2.0.0 addresses or the patches found on them.

## Alternatives considered
Supporting the base 1.0.0: worse stability and a larger test surface. Reusing the 2.0.0 patch addresses for
1.1.2: they point at unrelated code (the patch format refuses them by expected bytes anyway).
